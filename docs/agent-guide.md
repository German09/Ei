# Руководство по Ei для ИИ-агентов

[К руководству пользователя](../README.md)

Ei позволяет передать разработчику рабочий набор в 1С. Составьте запросы и алгоритмы, передайте их с параметрами и объясните, что проверить. После проверки прочитайте правки разработчика из открытого Ei и продолжите работу с актуальной версией.

## Какой инструмент выбрать

Получите схему из `tools/list` подключённого MCP-сервера. Имена инструментов в клиенте могут иметь префиксы. Для обмена наборами и клиентского выполнения нужны Ei и `1c_mcp` в целевой базе, а также открытый клиент 1С под тем же пользователем, от имени которого подключён MCP.

| Инструмент | Когда применять |
| --- | --- |
| `list_metadata_objects`, `get_metadata_structure`, `validate_query` | Найти объекты и поля в целевой базе и проверить текст запроса. |
| `create_variants` | Передать разработчику редактируемый набор для интерактивной проверки в Ei. |
| `get_variants` | Прочитать актуальные тексты, параметры и последние результаты из открытого набора. |
| `execute_query` | Получить небольшую выборку или сводку в чате. Для пакета запросов `result_index` выбирает результат по номеру с единицы. |
| `execute_code` | Выполнить код в нужном контексте. Используйте `server` для серверных операций, `client` для действий в открытом клиенте 1С. |
| `parse_nav_link`, `get_nav_link` | Прочитать присланную ссылку 1С или дать разработчику ссылку на объект или запись. |
| **EDT-MCP** | Изучить метаданные и исходники проекта, внести правки и диагностировать ошибки EDT. Подключается отдельно. |

[Документация 1c_mcp](https://github.com/German09/1c_mcp) · [Документация EDT-MCP](https://github.com/DitriXNew/EDT-MCP)

## Отправка набора

1. Передайте в `create_variants` короткое `description` до 60 символов и массив строк `sets`. Имя `name` должно быть допустимым идентификатором 1С.
2. В одной строке могут быть `query`, `algorithm`, `dcs`, `json`, `collection`, `process` и `comment`. Укажите `active_variant`, чтобы сразу открыть важный вариант. Варианты одной строки используют общие `parameters`. Для отдельных шагов используйте `children`; у дочерних строк свои параметры.
3. Сохраните `sets_id` из ответа. `sessions` показывает количество уведомлённых сеансов, а `rows` - пути строк. После нажатия **Консоль** набор появится в Ei. Разработчик сам выбирает и запускает нужные варианты.

### Пример для справочника валют

Сначала проверьте названия объекта и полей в целевой базе. В этом примере запрос и его обработка используют одну строку и общий параметр `ЧисловойКод`.

```json
{
  "description": "Проверьте валюту по числовому коду",
  "sets": [
    {
      "name": "ПроверкаВалюты",
      "active_variant": "query",
      "parameters": { "ЧисловойКод": "643" },
      "query": "ВЫБРАТЬ\n    Валюты.Код КАК ЧисловойКод,\n    Валюты.Наименование КАК КодISO\nИЗ\n    Справочник.Валюты КАК Валюты\nГДЕ\n    Валюты.Код = &ЧисловойКод",
      "algorithm": "Валюты = Варианты(\"Запрос\").Результат().Выгрузить();\nРезультат = Валюты.Количество();",
      "comment": "Проверьте строку в [запросе](set:ПроверкаВалюты/query), затем запустите [алгоритм](set:ПроверкаВалюты/algorithm) для подсчёта."
    }
  ]
}
```

### Из чего собирать шаги

- Храните запросы в `query`, а обработку результатов в `algorithm`. Для алгоритма задавайте значение переменной `Результат`. Параметр запроса `&Имя` доступен алгоритму как `Параметры("Имя")`. Другую строку получите через `Наборы("ИмяСтроки")`.
- `Варианты("Запрос").Результат()` может вернуть результат из текущего сеанса за последние 20 минут или запустить вариант. При изменении текста или параметров попросите разработчика выполнить запрос заново перед проверкой зависимых шагов. Для чисто читающего запроса `Результат(0)` позволяет явно выполнить его повторно.
- Для дат используйте `{"_date":"2025-01-01T00:00:00"}`, для вычисляемых параметров - `{"_expression":"выражение 1С"}`. Для ссылок и ключей записей передавайте целиком полученные описания `_objectRef` и `_recordKey`. Массив параметра строки становится списком значений.
- Если пользователю нужно редактировать таблицу, передайте её в `collection` с `columns` и `rows`. Запрос может получить её через вычисляемый параметр `Варианты("Коллекция").Данные()`. Формат `_table` предназначен для параметров прямого выполнения, а в строке набора используйте коллекцию или вычисляемое выражение.
- Для графического процесса используйте `process.object` и `process.steps`. Схема MCP принимает шаги `run`, `algorithm` и `for_each`. В `run` задайте `set` и `variant`, в `algorithm` - `code`, в `for_each` - вложенные `steps`. В первом шаге цикла текущий элемент доступен как `Объект()`. [Процессы в интерфейсе Ei](processes.md)
- В `comment` поясняйте ожидаемый результат и добавляйте ссылки. Для перехода внутри набора используйте `[текст](set:ИмяСтроки/query)` или `[текст](set:ИмяСтроки/&ИмяПараметра)`. В ответе человеку показывайте `url` от `get_nav_link`, если сервер его вернул, иначе используйте `navLink`.

## Чтение правок и результатов

- Вызовите `get_variants` с сохранённым `sets_id` или с `nav_link` от разработчика. Ei читает данные из открытой формы, в том числе несохранённые правки. Используйте `names` для отбора строк. Для чтения и правки графической схемы процесса откройте её в Ei или EDT.
- По умолчанию возвращаются последние результаты запусков. Для чтения только кода и параметров используйте `with_results: false`. Результат соответствует последнему запуску и может относиться к прежнему тексту. Для проверки после правки попросите выполнить вариант ещё раз.
- Перед повторным `create_variants` прочитайте текущую строку. Совпадение `name` обновляет присланные варианты и параметры, а также сбрасывает результаты строки. Уникальные имена позволяют добавить независимые шаги. Если пользователь продолжает работать с прежней версией, согласуйте её замену.
- Если ответ содержит `status: pending`, продолжите тот же вызов с `request_id` и исходными аргументами. Проверьте, что нужный набор открыт в клиенте правильного пользователя, если форма недоступна или строка отсутствует в ответе.
- Для прямой выборки передавайте небольшой `limit`, проверяйте `total` и `truncated`. В `execute_query` используйте `offset` для следующей страницы. В `get_variants` параметр `limit` ограничивает результат каждого варианта. Большие таблицы и значения, которые пользователю нужно видеть в исходном виде, выведите в Ei через набор. При анонимизации запрашивайте в контекст агента нужный срез или агрегаты. [Просмотр данных в Ei](../README.md#просмотр-данных-в-1с)

## Выполнение и согласование кода

- В `execute_code` передайте `execution_context` явно. Режим `statements` возвращает переменную `Результат`, `expression` вычисляет выражение, `module` предназначен для серверных функций и процедур. Параметры передавайте отдельно от текста кода.
- Когда сервер требует подтверждения, объясните пользователю, какие объекты, поля и строки затронет код. При `pending_approval` передайте прежние `code`, `mode`, `parameters`, `execution_context` и полученный `request_id`. При отказе, отмене или тайм-ауте завершите попытку и сообщите решение пользователю.
- Перед запуском записи проверьте режим базы в описании инструмента. В средах, где запись разрешена сразу, согласуйте область изменения до вызова. Для проверки подготовьте отдельный читающий вариант с отбором и количеством затрагиваемых объектов. Поле `dangerous_operations_allowed` в ответе отражает режим базы.
- Алгоритм, запускаемый из Ei в обычном автоматическом режиме, может повториться на сервере после клиентской ошибки или результата `Неопределено`. Для клиентского алгоритма возвращайте явное значение, а для прямого запуска из MCP используйте явный контекст. В алгоритмах и выражениях Ei используйте код без директив препроцессора.

## Правки и отладка в EDT

Сохраните набор через **Сохранить как** в каталог проекта EDT. Сохранённые исходники внешней обработки можно править в EDT. Оставьте тот же набор открытым в Ei, чтобы увидеть изменения сразу после сохранения. Если разработчик менял тот же фрагмент в Ei, согласуйте версию в диалоге загрузки.

Для остановки на точке останова используйте сеанс 1С под отладкой и сборку EDT, соответствующую сохранённым исходникам. Запускайте полный алгоритм из Ei. Для длительных серверных запросов, алгоритмов и процессов используйте [фоновое выполнение](background.md).
